# Nanar — contributor notes

Video player for the PC plugged into the TV, driven from a phone. Nanar opens on a folder of films
and series, shows the library in its own window (the TV page), and plays each video in mpv's window,
laid exactly over its own. A Python process (FastAPI, libmpv through python-mpv, pywebview) serves
the TV page and the phone's page (React, strict TypeScript, Vite). This file is the contributor
guide for humans and AI assistants alike; `README.md` covers what Nanar does.

## Commands

```bash
npm ci && uv sync                     # install (npm ci also points git at .githooks/)
uv run python scripts/get-libmpv.py   # libmpv-2.dll into vendor/ (Windows; Linux: apt install libmpv2)
npm run build                         # builds the pages into the Python package
uv run nanar D:\Films                 # opens Nanar on a folder (the last one when none is given)
uv run nanar --demo                   # made-up library, videos generated by mpv, own data dir
npm run dev                           # --demo, with the pages served by Vite (hot reload)
npm run check                         # everything CI runs, but gitleaks on the history
uv run python scripts/build-windows.py  # dist/nanar-<version>-windows.zip (PyInstaller, Windows)
uv run python scripts/screenshots.py  # docs/capture-*.png from the demo (Edge headless)
```

`npm ci` points git at `.githooks/`:

- `pre-commit` runs gitleaks on the staged changes (install: `scoop install gitleaks`,
  `brew install gitleaks`…);
- `commit-msg` rejects messages that don't follow the commit rules below;
- `post-commit` re-dates each commit at noon UTC (see Privacy);
- `pre-push` runs `check:private`, the date check and the commit check.

## Commits

Follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) strictly:

```
type(scope)!: imperative description, lowercase, no trailing period

Body explaining *why* (the diff already shows what).
```

- **Types:** `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `ci`, `chore`, `style`, `revert`.
- **Scope** is optional; `scripts/check-commits.mjs` holds the authoritative list of types and scopes.
- Header of 72 characters or fewer. One logical change and one type per commit.
- Descriptions read as behaviour, from the user's side ("bring the window back where mpv was").
- Code, comments and commit messages are in English; the UI and the user docs are in French.
- Work happens on `main`; every push runs the CI.

## Privacy of the public repository

Nothing personal goes into code, tests, fixtures, docs, commit messages or commit metadata.

- **No personal data:** tests and the demo use made-up titles, never the contents of a real film
  folder. No video file is ever committed (`.gitignore` refuses the usual extensions).
- **Identity:** commit with a GitHub `noreply` address. `check:private` rejects any other.
- **Times:** commit times show when someone works. The `post-commit` hook keeps only the day (noon UTC);
  `npm run fix:dates` re-dates unpushed commits made without the hook (rebases, other machines).
  Release tags are lightweight, as an annotated one would record the time.
- **Docs only when they belong in public:** no personal to-do lists, plans or notes. Local working notes
  stay in `.claude/` (ignored).
- **Secrets:** none needed. gitleaks scans the staged changes and, in CI, the history.
- `.private-patterns` (ignored, one regex per line) lists your own private strings: `check:private`
  scans tracked files and commit messages for them.

## Invariants (discuss before changing)

- **Plays everything mpv plays.** Video goes through libmpv, never through the browser engine:
  codecs (HEVC, AV1, AC3, DTS…), containers, embedded and external subtitles, HDR.
- **One window on screen.** While a video plays, mpv's window covers exactly the rectangle of
  Nanar's (`player.MpvSession._place`), which hides; when it stops, Nanar's window comes back where
  mpv's was, windowed or full screen as mpv was left. `F` toggles full screen in both, and the
  choice is remembered. The process is DPI-aware (`win32.declare_dpi_aware`), or Windows would
  render the video at a lower resolution and stretch it.
- **One mpv for a run of videos.** mpv keeps its window open on the last picture at the end
  of a video (`keep-open`); the next one (`Session.load`) plays in the same window after the
  controller's countdown, with `pause=no` and `start` as options of that file.
- **Progress** (`progress.py`, SQLite) is keyed by library folder and path inside it, saved every
  ten seconds of playback and on stop; past 90 % a video is watched (and stays so).
- **Pictures** (`thumbnails.py`): the user's poster first, else one frame grabbed by libmpv in the
  background (never anything from the Internet); their URL carries the file's age.
- **The TV follows the phone** (`set_view`): the page and the item a phone looks at; not the
  other way round.
- **mpv's callbacks never wait.** They come from mpv's event thread, and closing mpv waits for that
  thread: whatever they report runs on the controller's worker thread (`controller.py`).
- **Languages:** French audio first, then English; French subtitles, left off when the audio is
  already French (forced ones excepted). `Settings` holds the lists.
- **Local and private.** No telemetry, no account, no request to the Internet: the library is read
  from file names only. The server listens on the local network for the phones; who may call what
  is in `security.py`: this machine (loopback address _and_ loopback `Host`, against DNS
  rebinding), or a phone carrying the pairing key (`nanar_key` cookie, `HttpOnly`,
  `SameSite=Strict`, or a Bearer header). Anything that changes state needs a JSON body; no CORS
  header is ever granted; a WebSocket must come from the page's own origin.
- **Pairing:** one key per installation (`pairing.py`), shown on the TV as a QR code whose URL
  carries it in the fragment (never sent to a server or logged). Whoever sees the TV may pair: that
  is the point. `--new-key` unpairs every phone, `--local` listens on loopback only. A paired
  phone's manifest start URL carries the key, so that an iPhone home screen icon (cookies of its
  own) is paired too.
- **One name on every network:** `discovery.py` announces `nanar.local` (mDNS) with the
  addresses of the real adapters (`pairing.lan_addresses` leaves out WSL, Hyper-V, VPN tunnels,
  Bluetooth). The QR code holds the IP address, which always works; the page then moves to
  `nanar.local` when its request there succeeds, or offers a link to it (a browser may refuse a
  page's request to a `.local` name yet open it as a link), so that the cookie and the home screen icon belong to a
  name that outlives a change of Wi-Fi. `GET /api/health` is the one CORS-readable route, for that
  probe.
- **The phone's actions show on the TV** (mpv's OSD, `osd=True`); mpv's own keys already do.
- **User data lives outside the repository**, in the OS data directory (`platformdirs`), overridable
  with `NANAR_DATA_DIR`. The demo keeps its own (`demo/` inside it).
- **The desktop side asks before touching the system.** The Windows build offers once, on the TV
  page, to add a Start menu entry and "Ouvrir avec Nanar" on folders (`desktop/integration.py`:
  the user's own HKCU and Start menu folder only); nothing is written before a yes. Folders are
  opened, and those menus answered, from this machine only (`/api/open`, `/api/integration`).
- **One Nanar at a time.** A second launch hands its folder to the running one (`/api/open`) and
  stops; a page can't do that, only a process on this machine.
- **The Windows build has no console**: output goes to `nanar.log` in the data directory.
- **Screenshots show the demo only**, with `NANAR_SHOW_ADDRESS` (an address reserved for
  documentation) and a throwaway data directory: no real film, address or key.
- **Errors:** the API answers a code (`{"code": "nothing_playing"}`), which the pages turn into a
  French sentence.
- **Accessibility:** contrast ≥ 4.5:1 (tokens in `web/src/styles/global.css`), visible focus, every
  action reachable with the arrows and Enter on the TV, `prefers-reduced-motion` respected.

## Layout

- `src/nanar/`: Python package. `library.py` (reading release names with guessit, sagas and
  series), `player.py` (one mpv window per video, VLC-like keys), `controller.py` (the single place
  where state changes), `app.py` (API, WebSocket, pages, manifest), `security.py` and
  `pairing.py` (who may drive Nanar), `discovery.py` (`nanar.local`), `progress.py`,
  `thumbnails.py`, `watcher.py` (the folder, followed), `desktop/` (the pywebview window, Win32
  calls placing windows), `demo.py` (made-up library played from mpv's `lavfi` sources), `cli.py`.
  `tests/`: pytest (`tests/fakes.py` stands in for mpv and the window; `test_player.py` drives the
  real libmpv without video or sound).
- `web/`: the pages (Vite, React, CSS Modules, wouter). `/tv` is the TV page (`src/tv/`, arrow-key
  navigation in `src/lib/spatial.ts`), `/` the phone's page (`src/remote/`: pairing, then the remote). `public/` holds the
  icons; `scripts/make-icons.py` draws the PNG ones and `src/nanar/assets/nanar.ico`
  (the windows' icon; the process has its own taskbar identity, `win32.declare_app_id`). `npm run build` writes
  them into `src/nanar/web/static/` (ignored), which the Python package serves and ships.
- `scripts/`: repository checks, git hook helpers, `get-libmpv.py` (pinned libmpv build for Windows).

## Dependencies

Keep them few, and say why in the commit that adds one. Lock files (`uv.lock`, `package-lock.json`)
are written by their tool, never edited by hand. Dependabot proposes grouped updates every Monday.
libmpv is pinned by name and SHA-256 in `scripts/get-libmpv.py`.

## Releases

Semantic versioning. `0.1.0` comes out once Nanar is usable for real (library, remote, Windows
build). After it: `0.x.0` for a big batch of features, `0.x.y` for fixes that matter between them;
the smallest touches get no version of their own and wait for the next one. `CHANGELOG.md` (in
French, for users) says what each version brings; a lightweight tag `vX.Y.Z` makes
`.github/workflows/release.yml` publish the GitHub release with that version's notes, the Windows
zip and its SHA-256 (built on Windows by `scripts/build-windows.py`), and the Python package.
